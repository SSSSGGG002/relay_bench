# yjapi.manqiaotechnology.com — Claude 通道测试报告

采样时间 2026-09-11。方法：relay-bench quick 档（5 型号 × 88 次调用）+ 定向重复探针（90 次）+ 细粒度知识梯子（105 次）+ cluster 逐字比对。
站点限速 20 次/分钟，全程经本地限流代理（17 rpm）串行发送。

## 1. 结论

| 型号 | 声称截止 | 实测知识墙 | 判定 | 置信度 |
|---|---|---|---|---|
| claude-fable-5-1 | 2026-06 | 2025-12 | **假映射 → fable-5** | 很高（回显直接证据） |
| claude-opus-5 | 2026-05 | 2025-12 | **降级**，实为 2026-01 档模型 | 高 |
| claude-sonnet-5 | 2026-01 | 2025-12 | 与声称一致 | 中高 |
| claude-fable-5 | 2026-01 | 2025-12 | 与声称一致 | 中高 |
| claude-opus-4-6 | 2025-05/08 | ~2025 年中 | 与声称一致 | 中 |

**一句话：sonnet-5 / fable-5 / opus-4-6 大致是真的；opus-5 和 fable-5-1 是拿 2026-01 档模型冒充的。按 Opus 5 价格买到的是 Sonnet 5 一档。**

## 2. 决定性证据

### 2.1 fable-5-1 的模型回显（最硬的一条）
请求 `claude-fable-5-1`，响应体 `model` 字段回 `claude-fable-5`。不需要推理，站点自己说了。

### 2.2 知识墙：五个通道撞在同一个位置（2025-12）
每题 3 次，system 要求"只用训练知识、不确定答 UNKNOWN"：

| 题（日期） | opus-4-6 | sonnet-5 | fable-5 | opus-5 | fable-5-1 |
|---|---|---|---|---|---|
| K07 纽约市长（2025-11） | 0/3 | 1/3 ✓ | 1/3 ✓ | 0/3 | 0/3 |
| K09 TIME 年度人物（2025-12） | 1/3 | 2/3 ✓ | 1/3 ✓ | 2/3 ✓ | 2/3 ✓ |
| K11 超级碗 LX（2026-02） | 0/3 | 0/3 | 0/3 | 0/3 | 0/3 |
| K12 Anthropic 2026-02 发布 | 0/3 | 0/3 | 0/3 | 0/3 | 0/3 |
| K15 OpenAI 2026-04 发布 | 0/3 | 0/3 | 0/3 | 0/3 | 0/3 |
| K17 Anthropic 2026-05 发布 | 0/3 | 0/3 | 0/3 | 0/3 | 0/3 |

模型在 K07/K09 上愿意给具体答案，说明知道就答，墙不是拒答造成的。

- opus-5 声称截止 2026-05，却不知道 2026-02 的超级碗，**也不知道 2026-05 自己这一代的发布**。
- fable-5-1 声称 2026-06，同上。
- sonnet-5 / fable-5 声称 2026-01，墙在 2025-12，吻合。

### 2.3 至少存在两个不同后端
"现任日本首相"各问 6 次：

- opus-4-6：**6/6 石破茂**（2024-10 上任）
- 其余四个：全部高市早苗（2025-10 上任）

所以 opus-4-6 走的是另一个更老的后端，不是"一个模型套五个名字"。opus-4-6 知道教宗良十四世（2025-05）但不知道高市（2025-10），截止落在 2025 年中 —— 正好是真 4.6 的水平。

### 2.4 opus-5 与 sonnet-5/fable-5 同源
共享同一堵知识墙、同一份 usage 数字（20k 文档五个通道全部报 2659 input tokens）、同一档吞吐（49-65 tok/s）。cluster 创意题里 opus-5 / fable-5 / opus-4-6 的开头逐字相同（仅前缀，采样可能收敛，作旁证）。

## 3. 基础设施

- **上游是 AWS Bedrock，不是 Anthropic 官方 API。** 五个通道全部自报"由 Amazon Web Services 训练"。
- **注入了隐藏系统提示**，含搜索工具定义。多次回复漏出 `web.run(open_browser=...)`、`web.search`、`.tavily-search-tavily_search executed:` 等工具语法。注意 `web.run` 是 ChatGPT 的工具命名空间。
- **中转是 New API**：错误体 `"type":"new_api_error"`，限速 20 次/分钟。

## 4. 协议与计费问题

| 项 | 官方 | 本站 | 影响 |
|---|---|---|---|
| 消息 ID | `msg_01`+22 位 | `msg_01`+20 位 | ID 由中转生成 |
| `/v1/messages/count_tokens` | 200 | 404 | 无法预估费用 |
| `stop_sequences` | 生效 | **不生效** | 你的截断逻辑失效 |
| `max_tokens` | 生效 | **不生效**（要 16 给 736） | 账单和延迟不可控 |
| `max_tokens=999999` | 400 报真实上限 | 200 | 不泄露真实型号 |
| 默认思考 | Claude 5 系默认开 | **无 thinking 块** | 拿不到思考过程 |
| 参数校验 | Claude 5 对 temperature/top_k 必 400 | 全 200 | Bedrock 特征，非改写 |
| usage input | 真实 | 20k 文档报 **2659**（0.13×） | 计费数字不是上游真实值 |

注：ID 格式、count_tokens 404、参数全 200 这几项，在已知走 Bedrock/Kiro 池的 bitmiracle 上表现相同，属于**该类中转的通性，不能单独作为假货证据**。

## 5. 可用性

- 上下文：20k needle **3/3 全召回**，未截断（usage 少报≠截断）。
- 缓存：五个通道 `cache_read` 全部命中。
- 智力：`iq_reason` 五个通道全部 **6/6**，不是廉价降级货。
- 速度：TTFT 3.6-5.3s，49-65 tok/s。
- 限速：**20 次/分钟**，并发场景基本不可用。

## 6. 建议

- 想要 Opus 5 或 Fable 5.1 的**不要买这个站**，拿不到。
- 只要 Sonnet 5 / Fable 5 档位、且能接受 20 rpm 限速和参数不透传，可以用。
- 不要依赖 `stop_sequences`、`max_tokens`、thinking 块和 usage 数字。
