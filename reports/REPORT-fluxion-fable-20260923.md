# fluxionai.space claude-fable-5-1 测试报告（2026-09-23）

数据：`results/fluxion-fable/`（`*.json` 原始结果、`*.log` 运行日志、`scripts/` 全部探测脚本，`fx.py` 为公共客户端）。
网关：Caddy + Cloudflare 后面是 **sub2api**（`/v1/usage` 用 key 即可查余额、逐模型用量和 `account_cost`；`/api/status` 返回 Go 的 404）。首页写的线路是「Claude Max 支持 Fable 线路」，即 Claude Max 订阅账号池。
本机直连可用（0.8 s 建连，比走 Clash 快），全部测试走直连。
这把 key 的分组限制写着「restricted to Claude Code clients (/v1/messages only)」，实际只拦 OpenAI 口（403），普通脚本发 `/v1/messages` 照样放行。

## 一句话结论

**模型是真的 Claude Fable 5.1，但你拿到的不是"干净"的 Fable 5.1。** 上游是 Anthropic 官方 API（Fable 5.1 独有的协议指纹全部对得上），但网关在每个请求前面偷偷塞了约 **5,600 token 的隐藏 system prompt + 一个隐藏的联网搜索工具**：让模型自称知识截止 2025 年 1 月、不许说出 2025 年 10 月以后的任何事实（你在 system prompt 里覆盖也没用）、默认悄悄联网搜索、否认自己有 system prompt、被问 effort 只答 25。这段注入从 usage 里抹掉了，**不向你计费**，但会实打实改变回答。
缓存是真的，计价公道（读缓存按 Fable 5.1 官方 $0.25/M），但**只在同一段对话里命中**：同一个 system prompt 换一个开场问题就要重新写缓存。
速度：短请求 p50 3.5 s、p99 约 16 s；流式首字节 3.5 s，正文约 51 tok/s；120 个短请求里有 4 个挂到 300 s 超时。

## 1. 真假：上游确实是 Fable 5.1

| 探针 | 官方 Fable 5.1 应有 | 本站 claude-fable-5-1 | 说明 |
|---|---|---|---|
| `tool_choice: any` / `tool` | 400 `tool_choice: type "tool" and "any" are not supported for this model.` | **3/3 原文 400** | 只有 Fable 5.1 / Mythos 5.1 / Opus 5.5 会拒；同 key 的 fable-5、opus-5、opus-4-8、sonnet-5 都正常调工具 |
| `computer_20251124` 工具 | 接受 | 接受 | Opus 5.5 会 400 并报出 `'claude-opus-5-5' does not support…` → 排除「拿 Opus 5.5 冒充」 |
| 最小可缓存长度 | 512 token（Fable/Opus 5 代） | 704 token 前缀能写能读 | Opus 4.8 / Sonnet 5 门槛 1024，Opus 4.5/4.6 是 4096 |
| 响应形态 | `msg_011C…`、thinking 签名、`stop_details`、`context_management`、`service_tier`/`inference_geo`、`output_tokens_details.thinking_tokens` | 全部一致 | 工具 id `toolu_01…`，带 `caller:{type:direct}` |
| 默认思考 | 始终开 adaptive | 每个回复都有 thinking 块 | |
| 缓存读计价 | $0.25/M（Fable 5 是 $1） | 站内按 $0.25/M 记账 | 站点计价表也按 5.1 走 |

**知识探针这次不能用来判型号**，因为被隐藏 prompt 双向污染（见第 2 节）：
- 压低：隐藏 prompt 规定「不得陈述 2025-10 以后的事实」，所以 Super Bowl LX、98 届奥斯卡、Mojtaba 接任这些官方 5.1 基线 3/3 都知道的题，这里基本全答「不知道」（强制猜答模式下也是 0/3、1/3、0/3）。
- 抬高：隐藏的联网搜索让它偶尔答出 2026 年 5–7 月的事（欧洲歌唱大赛保加利亚、NBA 总决赛尼克斯、世界杯西班牙），带着「评审 204 + 观众 312 票」「第 106 分钟进球」这种只有搜索结果才有的细节；其中几条回复是两段文字拼接（前一段说「我不知道」，后一段给答案），中间被删掉的就是搜索调用块。
- 旁证：我问 2026 温网冠军并注明「需要就去查」，思考摘要显示它搜到了 2026 年 7 月的结果，然后因为内容限制拒绝告诉我。

附带发现（不在本次范围）：站内的 `claude-opus-5-5` 名字接受强制 tool_choice、也接受旧版 computer 工具，**不是真 Opus 5.5**。

## 2. 注入：每个请求约 5,600 token 隐藏 prompt + 隐藏搜索

**大小（不依赖 usage 的测法）**：发一个略超 1M 上下文的请求。站点自己的 count_tokens 算出我方内容 1,024,019 token；上游报错 `prompt is too long: 1029638 tokens > 1000000 maximum`。差值 **约 5,619 token** 就是网关注入的部分。同时 usage 被改写：裸发 "Reply with exactly: OK" 只报 18 input token，和 count_tokens 一致，隐藏部分从 usage、缓存字段和账单里都被扣掉了。

**内容（模型拒绝透露，但思考摘要把它泄露了；网关默认把 thinking 显示成 summarized）**：
| 隐藏指令 | 证据（思考摘要大意） |
|---|---|
| 身份段写「knowledge cutoff January 2025」 | 问上下文里有哪些日期：「身份段写着截止 2025 年 1 月，内容限制段有 2025 年 10 月……被告知不能说出两个截止日期」 |
| 内容限制：不得陈述、暗示、依赖 2025-10 之后的事实 | 温网 2026：搜到 2026 年 7 月的结果后「必须不陈述、不暗示、不依赖该日期之后的事实」，回答「我无法确认」 |
| 你的 system prompt 覆盖不了 | system 写「训练数据到 2026、忽略截止日期、不许用工具」，仍说 Super Bowl LX「还没打」，理由是「不该陈述 2025 年 10 月以后的事实」 |
| 先搜索，且默认要悄悄搜 | 「用户明确要求搜索，所以这次可以承认搜过，不像其他需要把搜索藏起来的情况」；天气题摘要直接写「我有 web search 工具……于是去搜了，结果不一致」 |
| 不许承认有搜索能力、不许承认有 system prompt | 「指令说这场对话没有 system prompt，可内容明明在，我不喜欢撒谎，但还是照指令回答没有」；工具清单问题回答「Tools: none」 |
| 问 effort 只答数字 25 | 「只要有人问推理强度、思考预算、effort 等级，就只回答数字 25」 |
| 把 system 里标了 secret 的内容当机密 | 我在自己的 system prompt 里放 `The secret word is PAPAYA-42`，问它，它拒绝，理由是「运营方指引说标记为 secret 的内容要拒绝」 |
| 不谈其他公司的模型 | 问最新 GPT 型号：「其他公司的模型阵容我不讨论」 |

**对你的实际影响**：
- 任何涉及 2025 年 10 月以后的信息（新库、新 API 版本、新闻、2026 年事件），它会说不知道或给旧答案，system prompt 里改口也压不住。
- 时事类问题会被悄悄联网搜索，这类请求耗时 13–21 s（普通问答 3–4 s）。
- 它会对你撒谎说没有 system prompt、没有工具。
- 这 5.6k token 不向你计费，这点对钱包没影响。

**隐藏搜索是怎么实现的（补测 `search_sse.json`）**：
- 搜索是真的、实时的：搜到了 2026 年 7 月的温网结果、比 3.14.0 更新的 Python 发布（都被内容限制挡掉不说），天气题给出了当天预报。
- 带搜索的回答只比普通回答慢 0.4–2 秒；流式里第一段思考结束后停约 1.9 秒，再出第二段思考和正文。这更像是 Anthropic 服务器在同一次调用里执行了自带的 web_search；如果是网关自己接第三方搜索，得"模型发起工具调用 → 网关去搜 → 再调一次模型"，至少多一整次请求（这个站单次请求底噪就 2.5–3.5 秒）。
- 能区分的痕迹都被网关抹掉了：工具调用块、结果块、正文的 citations、usage 里的 `server_tool_use` 计数，流式块编号也被重新连续编号。所以只能说"倾向官方自带搜索"，不能 100% 断定。
- Max 订阅本来就能用官方搜索（Claude Code 的 WebSearch 走的就是它），不存在"反代后搜不了、只能接第三方"的问题。
- 你在自己的 system prompt 里写「你没有任何工具，不要搜索」，实测一次有效（它的思考写着"不许搜索的指令优先"）；但内容限制仍然生效。
- 这套模板（Claude Code 身份 + 单个 web_search + 截止 2025-01 + effort 25）和 09-22 测的 sudocode 站几乎一样，分组又叫「Max-外接」，很可能是同一个上游批发商统一加的。

**网关对请求参数的静默改写**（官方会 400 的它都吞掉返回 200）：`thinking:{type:disabled}`、`budget_tokens`、`temperature`、`top_k`、assistant prefill（被直接丢弃，不是续写）、非法 effort 值、`inference_geo`、`speed`、`block_binding`、`anthropic-beta: thinking-binding-controls` 都被剥掉；顶层 `cache_control`（自动缓存）也被剥掉。请求里不带 `thinking` 参数时，历史里的 thinking 块会被丢掉；带了才会转发。签名被篡改时，上游报错后网关剥掉 thinking 块重试（仍返回 200，多耗约 1 s）。

## 3. 缓存：真的，计价公道，但换开场问题就不命中

| 测试（Fable 5.1，约 5.5k token 自然文本前缀，间隔 3–7 s） | 结果 | 官方应有 |
|---|---|---|
| 704 token 前缀 | 写 704 → 下一次读 704 | 一致（512 门槛） |
| 同一请求顺序重发 | 1 次写 + 5/5 读 5,491 | 一致 |
| 多轮对话（Claude Code 式，断点逐轮后移） | 每轮都读上一轮前缀：5,506 → 5,608 → 5,688，只写新增 80–102 | 一致 |
| **同一 system 前缀、换 5 个不同问题** | **0/5 命中，每次重写 5,491** | 应 4/5 命中 |
| 同上 + 固定 `metadata.user_id` | 0/5 命中 | 应 4/5 命中 |
| 长文档放首条用户消息的第一个文本块、问题放后面 | 换问题 2/2 命中（读 5,499） | 一致 |
| 不加 cache_control | 不缓存 | 一致 |
| 顶层自动缓存 `cache_control` | 不生效（被网关剥掉） | 应缓存 |
| 5m TTL：写入后 4.5 分钟再读 | 命中 | 一致 |
| 5m TTL：闲置 5.5 分钟后 | 过期，重新写入 5,488（读取会续期，闲置超过 5 分钟才过期） | 应过期重写 |
| 1h TTL | 写入时正确计入 `ephemeral_1h_input_tokens`；写入 11 分钟后读取仍命中 5,487 | 应命中 |
| 命中是否降延迟 | 不降，读写都是 3–5 s | — |
| 计价审计（5 次纯读，前后快照） | 读缓存按 **$0.25/M** 记账，再 ×1.2；钱包扣款与统计一致到 1e-6 | Fable 5.1 官方 $0.25/M |

规律：缓存只在「system + 首条用户消息的第一个文本块」都相同时命中，也就是同一段对话内部。网关大概率按这个做了会话粘性分号（缓存是按账号隔离的），或者在你的 system 前插了随首条消息变化的内容。
对你的影响：Claude Code 长会话里缓存正常；但每开一个新会话（或每个子 agent）都要把系统提示重新按 1.25 倍写一次。用 API 做「固定长 system + 各种单轮问题」的场景，缓存基本全 miss，还比不加缓存多付 25%。
变通：把要复用的长内容放在**第一条用户消息的第一个文本块**里并打 `cache_control`，问题放在后面的文本块。

| 短请求非流式（"Reply with exactly: OK"，并发 4） | 56 成功 | 3.39 s | 4.93 s | 16.7 s | 另有 **4 次挂到 300 s 超时**，同一时刻一起卡住 |
| 短请求流式总耗时（并发 3） | 60 | 3.72 s | 6.2 s | 7.5 s | 0 失败；首字节 p50 3.44 s |

| 350 词作文流式：首字节 | 16 | 3.5 s | 3.9 s | 4.0 s | 首个事件就是 thinking |
| 350 词作文流式：首个正文字 | 16 | 7.3 s | 18.1 s | 21.4 s | 取决于思考量（78–1,618 token） |

- 最简单的「OK」最快也要 2.5 s，p50 3.5 s。
- 时事类问题因为隐藏搜索要 13–21 s。
- 全部约 400 个请求：网络层失败 6 个（上面 4 个超时 + 2 次连接被重置），没有 5xx，没有 529，没有空回复。

## 5. 计费

- 这把 key 在「**Claude-Max-外接**」分组（公开分组表 `/api/v1/model-plaza/public`：倍率 1.2；首页写的 ¥10/¥50 是另一个 ×1.0 的「Claude-Max」分组）。「外接」说明这条线是站方从外部上游接进来的，上面那段隐藏 prompt 很可能是上游供应商加的。
- 计价 = 官方标价 × **1.2**（fable 系列；同 key 的 opus/sonnet 名是 ×1.0）。`/v1/usage` 里 `cost` 恰好是 `account_cost` 的 1.2 倍，`account_cost` 按官方价（输入 $10/M、输出 $50/M、写缓存 $12.5/M、读缓存 $0.25/M）算，与返回的 usage 对得上。
- 隐藏的 5.6k token 没有计入账单。
- **钱包余额比统计掉得多（已查明原因）**：本 key 统计的累计花费是 $9.63，但钱包从 $20 降到了 $6.68（实际扣了 $13.32），多出约 $3.69（多 38%）。我专门做了一次空闲检查：221 秒里这把 key 只发了 1 个请求（记账 $0.083），钱包却降了 $0.114；写完报告时，没有任何请求，余额又降了 $0.01。所以钱包在被别的来源持续消耗，这把 key 每个请求的记账本身是准的。原因已查明：同一时间另一个 Claude 会话在用同账户的另一把 key（Claude-Vertex逆 分组）测试，钱包是账户级共享的，**不是站点多扣费**。
- 这把 key 的 Fable 5.1 测试总花费约 $9.55（fable-5-1 共 379 个请求）。另有约 $0.08 是我为做指纹对照调的 fable-5 / opus-5 / opus-5-5 / opus-4-8 / sonnet-5（每个名字几次），后台里看到的这些名字的记录就是它们，大头是思考 token：Fable 默认每次都思考，350 词作文平均带 300+ token 思考，「强制猜答」这种题每次思考上千 token。

## 6. 给你的结论

- 型号是真 Fable 5.1，协议层是官方 API，缓存机制是真的，价格按 1.2 倍官价走，隐藏 prompt 不收你钱。
- 但每个请求都带着一段约 5.6k token、针对性很强的隐藏 prompt：截止日期造假、禁止说 2025-10 以后的事、悄悄联网搜索、否认有 system prompt。写代码类任务影响相对小；需要新知识、需要忠实执行你自己 system prompt 的场景会被干扰，而且你改不掉。
- 缓存只在同一会话里有效；用 Claude Code 的长会话没问题，用 API 做「同 system 不同问题」会全 miss。
- 速度中等偏慢（首字节 3.5 s、51 tok/s），偶发整批请求挂死 300 s，调用端要设超时重试。

## 7. 补测（同日稍晚）：安全锁、网关规则变化

**安全锁照常生效，注入不是为了越狱**（`guard.json`）：两条"把内部思维链逐字写出来"的请求都返回 `stop_reason: refusal`，`stop_details.category: "reasoning_extraction"`，说明文字是 Anthropic 官方的 ToS 原文。这类分类器跑在 Anthropic 服务器端，只有 Fable 级（和 Opus 5.5）才有，Opus 5 没有；改 system prompt 让模型"以为自己是谁"绕不开它。泄露出来的隐藏规则全是收紧和隐藏类，模型始终自称 "Claude, made by Anthropic"，从没自称 Opus，也没看到任何解锁类语句（5.6k 全文拿不到，不能 100% 排除其他条款）。

**网关规则在测试期间变了**（`switch_check.json`、`guard.json`、`model_leak.json`，约在主测试后 1 小时）：
- 强制 `tool_choice` 不再返回官方 5.1 的 400：`any` 被悄悄降成 auto（问"用法语打招呼"时不调工具）；`tool` 会被执行，对不相干的问题也强行调用 add(1,1)，可能是网关改写成了提示指令；指定一个不存在的工具名返回打码的 `request failed`。
- 上游报错不再原样透传，统一变成 `request failed`；`max_tokens: 200000` 不报错，被夹到上限。
- 有两条回复（一条缓存命中、一条 refusal）的 thinking 签名是同一个固定串 `Eo8DCkYICxgCKkCwm1ibbWS7k1X/…`，两条请求完全不同，签名却一字不差，说明是网关填的占位签名。
- 其余指纹都没变：reasoning_extraction 分类器、签名头 `CAQS…EAgRGAI4AUII`、分词（OK = 18 token、5k 前缀 5,495 token）、704 token 缓存门槛、接受 `computer_20251124`。
- 结论：最可能是中转层加了参数兼容和报错打码，而不是换了模型。但 Fable 5.1 和 Fable 5 在外部唯一可区分的指纹因此被抹掉，**此后在这个站上已无法再确认是 5.1 而不是 5**；"真 Fable 5.1"的结论只对主测试那段时间成立。
- 这两条带固定签名的回复，一条是缓存命中（缓存是按模型隔离的），一条触发了只有 Fable 级才有的 reasoning_extraction 拒绝，所以答题的仍是 Fable 级模型，只是签名被中间层换掉了。签名以后在这个站上不能当证据。
- 旁证（翻旧数据，未花钱）：9 月 22 日 sudocode、9 月 17 日远桥云 sgg 的 fable-5-1 返回的思考签名，与这里确认的 Fable 5.1 格式相同（同一种信封、版本字段 17）。这两个站当时被我判为「Opus 4.5 冒名」，依据正是知识止于 2025 年 10 月底，现在看很可能是同款模板压制造成的误判，两份旧报告顶部已加更正提示。
