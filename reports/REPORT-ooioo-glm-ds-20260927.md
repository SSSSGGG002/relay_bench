## 一句话结论

**glm-5.3-flash：模型是真的 GLM-5.3-Flash 权重，但不是智谱官方 API，而是一套自建的 SGLang 部署，默认几乎不思考。**
1. **身份**：
   - 响应带 SGLang 特有的 `metadata.weight_version` 字段；id 是 32 位 hex；回显 `GLM-5.3-Flash`；站点账单里的上游模型名也是 `GLM-5.3-Flash`。
   - 与官方 key 的隐式缓存**双向 0 命中**（OpenAI 口和 Anthropic 口都是 0）。真走智谱后端的 ikuncode、junliai 上次都是 4/4。
   - 分词、模板 token 和官方逐位一致，开思考后智力也和官方同档。所以权重没换，只是服务端不是智谱。
2. **默认档位太低**：
   - 不带参数时，写代码题思考 0 字（官方 1.5–2.1 万字）；27 题 ×2 只对 **33/54**（官方 47/54），连简单推理题都会错。
   - 加 `reasoning_effort: "max"` 后 **48/54**，作答正确率 98%，官方是 96%。
3. **思考参数有坑**：
   - OpenAI 口的 `thinking: enabled` 被忽略。
   - "关思考"（`thinking: disabled` / `reasoning_effort: none` / `enable_thinking: false`）反而让模型在后台想 3–5.5 千 token：思考内容藏起来但照样计费，首个正文要等 39–81 秒。
   - 只有 `reasoning_effort` 能打开思考，而且档位含义和官方不同：low 比 high 想得还多。
   - Anthropic 口带 `thinking: enabled` 或 `adaptive` 会完整思考，所以 Claude Code 用起来没问题。
4. **速度与稳定性都好**：
   - 顺序首 token p50 **0.69 s**、p99 **1.93 s**（官方 0.51 / 1.49，ikuncode 1.77 / 2.62）。
   - 30 并发 ×2 全部成功，总耗时 p99 3.0 s。
   - 30 分钟 soak 179/180，唯一一次失败是站点限流。
5. **其余能力**：缓存空闲 7 分钟仍命中；47.8 万 token 长上下文三针全中；图片输入正常。
6. **价格**：¥0.525 输入 / ¥1.75 输出 / ¥0.105 缓存命中（每百万），计费公式逐条核对无误。比官方标准价（¥0.8 / 2.8 / 0.23）便宜三到五成，但比官方限时五折价（¥0.4 / 1.4 / 0.115）贵。

**deepseek-v4-flash：是 DeepSeek-V4-Flash 0731 老版本，与 sudocode / ikuncode / teamorouter 卖的 v4-flash 同款，不是官方现在这个名字对应的 V4.1-Flash。**
1. **版本证据**：
   - 知识阶梯从 K01（2025-05）起全部答"不知道"；关思考智力 64%，0731 的历史值是 50–67%，V4.1 是 88%。
   - 站点渠道 42 的上游手里同时有两个版本：同样三道 2025 年知识题，请求名写 `deepseek-v4-flash` 时全答"不知道"，写 `deepseek-v4.1-flash` 时全答对。
2. **上游**：Cloudflare 后面一个叫 `quark` 的网关，usage 是 DeepSeek 官方格式。没有注入，参数都守规矩（关思考、max_tokens、stop、JSON 模式、工具调用正常，非法参数返回 400）。
3. **主要问题是上游容量**：
   - 站点账单里有 126 次上游 429 "server overloaded"，约占全部尝试的 16%。站点会自动重试，大部分用户看不到，但会拖慢响应。
   - 30 并发时第一轮 12/30 直接失败，成功请求的首 token 中位数 13.6 秒。
   - 30 万和 47.8 万 token 的长请求等了 4–7 分钟后都被 429 拒掉（19 万 token 正常）。
4. **平时速度**：顺序首 token p50 2.23 s / p99 3.50 s；30 分钟 soak 176/177（1 次站点限流），但最慢一次 32 秒；吞吐 90 tok/s（每 chunk 约 5 token）。
5. **缓存和价格**：缓存很好，空闲 7 分钟仍命中，命中只收输入价的 2%。价格 ¥0.525 / ¥2.10 / ¥0.0105。

**站点层面还有两点**：
- 每个用户每分钟最多 80 次请求（「1分钟内最多请求80次」），同一账号的多把 key 共享这个额度。
- 用 key 就能查逐条账单（`/api/log/token?key=`），里面带上游模型名和各项倍率。

## 10. 方法学备注

- **判定「不是智谱后端」的依据**：跨账号隐式缓存双向不通，加上 SGLang 特有字段、32 位 hex id、账单里的上游模型名。分词和模板 token 一致只能说明是同一套权重，不能说明是官方服务。
- **xcache 的 Anthropic 口读取**：第一轮和 OpenAI 口读的是同一篇文档，读到的是中转自己刚写的缓存，那轮数据作废。`glmsuite.py` 已改成两个接口各用一篇独立文档，复测结果为 0/2。
- **DeepSeek 版本的判断**：看知识阶梯（0731 全部不知道，V4.1 到 2025-10/11）加关思考智力（0731 五六成，V4.1 八成半以上）。最短请求 token 数在不同托管方之间不一样（官方 35、方舟 88、这家 9），只能用来区分上游，不能区分版本。
- **ooioo 的"关思考"**：有 3,000 多个空 chunk，completion token 却很大。判断关思考是否生效，不能只看 reasoning_content 是否为空，要同时看 completion_tokens 和首个正文时间。
- **站点每用户 80 次/分钟的限速**：同一账号的多个渠道、多把 key 共享。测延迟时要让这些渠道串行、控制节奏（`glmsuite.py lat --lat-serial … --lat-gap 2`），否则顺序测试会被站点限流污染。
- **`/api/log/token`**：只返回最近 1000 条，而且会把 `id` 重新编号。跨次拉取要按 `request_id` 去重，`glmsuite.py logs` 已改。
