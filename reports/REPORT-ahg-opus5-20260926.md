# ahg.codes · claude-opus-5 测试（对比 ikuncode / apizn / bitmiracle）— 2026-09-26

sub2api 站，key `sk-4a80…116d`，实扣倍率 0.8（官方价 $5/$25 × 0.8）。全部在 Mac 直连测。数据 `results/ahg/`。

## 结论
**不推荐。** 一把 key 背后是 Kiro 池和 `msg_011C` 池随机轮换（偶尔还有模板池），011C 池里约一半请求是 2024 年那一代的老模型。智力 12 道区分题 2/12；30 分钟 soak 失败 11.7%；token 计数虚高 2.5–3 倍，截断时输出按 max_tokens 的 2 倍计费。同一缓存工作量实扣是四家里最贵的。

## 3. 缓存与计费（与另外三家同一脚本、同一文本）
- 同一段文本的 token 数：27k 字符在 011C 池报 34,134（ikun 11,967，2.9 倍）；54k 字符报 57–70k（2.5–3 倍）；112k 字符报 142,970（3 倍）。同一文本多次请求计数也不一样。
- Kiro 池：system 前缀整段不计费（actual 35,850 / billable 28）。只对 messages 计费。
- 多轮 5 轮在两个池之间来回切换，缓存基本不命中，每次换池都重新写入（1.25 倍），写入量还是按虚高后的数计。
- 按显示 usage × 官方价 × 0.8 计算：同一脚本 **$3.46**（ikun K2 $0.52 / K1 $0.66 / apizn $0.80 / bitmiracle $1.83）。
- 空闲时逐条核对：扣费 = 显示 usage × 价格，钱包变化与 key 统计一致，没有隐藏扣费。**但 011C 池在截断时把 output 报成 max_tokens 的 2 倍并照此扣费**（max_tokens 300 → 报 600、扣 600，3/3；IQ 里 max_tokens 16000 → 报 32000）。
- 当天钱包比 key 统计多掉约 $1.58，原因未明（后续逐条对账都一致；可能是同一钱包下的其他 key）。

## 4. 花费
测试共计约 $7.7（钱包从 $10.02 降到 $2.34），大头是缓存脚本（token 虚高）和 3 次被翻倍计费的 IQ 截断。
